# Сайт для автоматизации заказов

Лёгкое веб-приложение для приёма заказов и их сопровождения от оплаты до отправки.
Node.js (встроенный `node:sqlite`) + ванильный HTML/JS, плюс три npm-пакета
для генерации PDF-этикеток (pdfkit, svg-to-pdfkit, bwip-js). Для доставки — прямая
интеграция с Ozon Delivery API (встроенный `fetch`, без дополнительных пакетов).

## Что уже умеет

- **Новый заказ** (`/`) — форма ручного ввода данных из переписки ВК после оплаты:
  ТК (СДЭК/Озон/...), адрес ПВЗ, ФИО, телефон, товары (модель/цвет/разъём из списков,
  кол-во, цена, серийный номер), сумма доставки. Итог считается автоматически.
- **Новый заказ по шагам: Клиент → Товары → Доставка → Проверка.** На шаге «Доставка» всё заполняется само:
  коробка (первая из Настроек → Каталог, можно выбрать другую), вес посылки (коробка + вес товаров по каталогу),
  ПВЗ СДЭК/Ozon по адресу (если подходит несколько — выбор из вариантов) и стоимость доставки со страховкой —
  она сразу ставится в «Сумму доставки». Это только расчёт: отправление в ТК не создаётся. При сохранении
  посылка, ПВЗ и расчёт попадают в заказ. Сумму можно поправить руками — тогда расчёт её не перезапишет.
- **Генератор серийников** — формат `[КодМодели][R+ревизия][Цвет][Разъём][№№№№]`,
  например `AL1R03TT0043`. Счётчик номера общий на модель. Если номер ещё нигде не
  сохранён в заказах — повторный клик по ⚡ меняет только буквы цвета/разъёма, номер не
  расходуется; если уже занят — выдаётся следующий по счётчику.
- **Доска** (`/board.html`) — канбан вместо Trello: колонки «Новый → Собрать → Собран →
  Отправлен → Доставлен», карточки перетаскиваются мышью между статусами.
- **Сборка** (`/assembly.html`) — чек-лист того, что нужно собрать: каждый товар отдельной
  строкой (кол-во, цвет, разъём, серийник), по умолчанию только заказы в статусе «Новый»/
  «Собрать». Дата сборки редактируется прямо в таблице; кнопка «🏷 PDF» скачивает этикетку
  и, если дата ещё не проставлена, сама подставляет сегодняшнюю и сохраняет её.
- **Все заказы** (`/orders.html`) и **доска** — товары с одинаковым названием сворачиваются
  в одну строку («Автоматический лоадер 3шт»); раздельный цвет/разъём/серийник по каждой
  единице смотрите на вкладке «Сборка» или в самом заказе.
- **Цветные метки** — у ТК, цвета товара и разъёма есть кружок-индикатор (СДЭК зелёный,
  Озон синий, цвета товара — максимально близкие к реальным, разъёмы — просто два разных
  цвета для быстрого различения). Настраивается в `db.js` (`swatch` у каждого пункта каталога).
- **Чеки** — на странице заказа можно прикрепить один или несколько файлов (скриншот оплаты
  из ВК, чек из «Мой налог» и т.п.), скачать или удалить их позже. Хранятся в `data/uploads/`
  (не в git), список виден в заказе, счётчик 📎 — в таблице заказов и на доске.
- **Серийные номера** (`/serials.html`) — таблица как лист «Продажи» в Google-таблице: #, С/Н, ревизия,
  цвет, разъём, дата сборки, примечание и заказ; поиск, сортировка по номеру. Номера, выданные до CRM,
  переносятся кнопкой «⬆ Импорт» (скопировать колонки A–G листа «Продажи» и вставить) или по одному «＋ Номер».
  Такие номера хранятся в реестре (`serial_registry`) и считаются занятыми; всё до последнего номера из реестра
  генератор считает выданным и продолжает со следующего. Счётчик общий для всех ревизий модели.
- **Этикетка 58×40мм (PDF)** — у каждого сохранённого товара (на странице заказа или на
  вкладке «Сборка») есть кнопка «🏷 PDF»: лого TACLAB + значок RU, модель/модификация/дата
  сборки/серийный номер, штрихкод Code128 серийника. Дата сборки подставляется сегодняшней
  при первом скачивании, если её не задали вручную, и с этого момента фиксируется.
- **Экспорт в CSV** — кнопки на страницах «Все заказы» и «Серийные номера» скачивают
  `orders.csv` / `serials.csv` (UTF‑8 с BOM, разделитель `;`), которые открываются в
  Google Таблицах через «Файл → Импортировать».
- **Ozon Доставка** (`/settings.html`, вкладка «Ozon Доставка») — отправка заказов в Ozon Delivery API как черновик
  отправления (после оплаты в ВК заказ оформляется на доставку через сеть Ozon, без
  привязки к товарам на самом Ozon):
  - в Настройках (`/settings.html`) вводятся `Client ID`/`Client Secret` частного приложения Ozon Delivery
    (Настройки → Управление частными приложениями в кабинете Ozon Delivery), там же —
    выбор уже существующего в кабинете метода отгрузки, шаблоны коробок и % страховки;
  - на странице заказа — блок «🚚 Ozon Доставка»: ID ПВЗ покупателя (необязателен — подбирается
    по адресу ПВЗ заказа), кнопка «Рассчитать доставку»
    (предварительный расчёт стоимости/срока), «Создать черновик в Ozon» (`/v1/order/create`
    — тот самый черновик), «Подтвердить к отгрузке» (`/v1/posting/approve`) и скачивание
    этикетки Ozon (`/v1/posting/label`);
  - авторизация — server-to-server (`client_credentials`), без браузерного OAuth, как у ВК;
    клиент (`lib/ozon.js`) сам обрабатывает анти-DDoS редирект Ozon (testcookie) при первом
    запросе. Токен и cookie живут в памяти процесса, а не в базе.
- **Мой налог** (`/settings.html`, вкладка «Мой налог») — чеки самозанятого (`lib/npd.js`):
  - используется API веб-кабинета lknpd.nalog.ru (официального API для этого у ФНС нет; если ФНС
    его поменяет — править `lib/npd.js`); вход по ИНН + паролю от ЛК налогоплательщика или по СМС,
    пароль не хранится — только refresh-токен сессии;
  - на странице заказа блок «🧾 Чек «Мой налог»»: предпросмотр позиций (товары + доставка),
    дата расчёта, «Сформировать чек», публичная ссылка на чек для покупателя, аннулирование
    («сформирован ошибочно» / «возврат средств»).
- **СДЭК** (`/settings.html`, вкладка «СДЭК») — заказы через СДЭК API v2 (`lib/cdek.js`):
  - в Настройках: Account / Secure password (Интеграция → API в кабинете СДЭК), тестовый режим
    (`api.edu.cdek.ru`), ПВЗ отправки (поиск по адресу), тип заказа (2 «Доставка» — любой договор,
    1 «Интернет-магазин» — только договор с ИМ), тарифы до ПВЗ/постамата, отправитель;
  - на странице заказа — блок «🟢 СДЭК» (показывается, если транспортная компания — СДЭК):
    ПВЗ получателя подбирается по адресу (или код вручную), «Рассчитать доставку»
    (`/v2/calculator/tariff`, страховка от стоимости товаров, сумма пишется в «Сумму доставки»),
    «Создать заказ в СДЭК» (`/v2/orders`), статус, этикетка (`/v2/print/barcodes`, A6), отмена;
  - вес и габариты посылки общие для Ozon и СДЭК (блок «📦 Посылка»); СДЭК получает стороны
    в сантиметрах (мм / 10 с округлением вверх).

- **Бухгалтерия** (`/accounting.html`, только для администратора) — замена листа «Бухгалтерия» из Google-таблицы:
  - журнал «История платежей»: дата, поступление, списание, назначение, категория и отметки «на гарантии»,
    «облагается налогом», «доставка со счёта ТК»; добавление/правка/удаление прямо на странице, поиск,
    фильтр по месяцу, экспорт `ledger.csv`; любую запись (возврат, доплату, старую продажу) можно привязать к заказу —
    из журнала заказ открывается по ссылке, а в карточке заказа администратор видит блок «💰 Бухгалтерия» с его записями;
  - **автозаполнение**: каждый оплаченный заказ сам становится записью «Продажа» (поступление — итог заказа,
    списание — доставка, гарантия — если в заказе изделие из каталога моделей). Изменили заказ — запись
    обновилась, отменили — убралась. Заказы с сайта попадают после подтверждения оплаты. Запись, исправленную
    вручную, синхронизация больше не трогает (кнопка «⚡ Из заказа» возвращает автозаполнение);
  - итоги как в формулах таблицы: «Грязные» (поступления − списания), «Чистые» (без денег за изделия на гарантии,
    срок гарантии задаётся периодами в ⚙ — «с начала 92 дня, с даты X — 30 дней»: каждая продажа
    получает срок, действовавший на её дату, а у отдельной записи срок можно задать вручную), налог (4% с облагаемых поступлений), долг перед доставкой (доставка со счёта ТК −
    пополнения счёта), сверка с фактическим остатком в банке, прибыль месяца за вычетом постоянных расходов;
  - **счета Ozon и СДЭК**: их API баланс не отдают, поэтому остаток вписывается из личного кабинета («Записать
    остаток»), а дальше сайт считает сам: записанный остаток − доставка, списанная со счёта этой службы после
    записи, + пополнения этого счёта после записи. Служба записи определяется по ТК заказа или по назначению
    («Сдек»/«Озон»). Если расчётный остаток ниже порога из ⚙ (по умолчанию 1 000 ₽) — предупреждение;
  - **импорт истории**: выделить в таблице колонки A–E листа «Бухгалтерия» с заголовком, скопировать и вставить в
    окно «⬆ Импорт» — категории подбираются по назначению, повторно вставленные строки не задваиваются.
    Автозаполнение из заказов начинается с даты первого запуска (меняется в ⚙), чтобы продажи, уже внесённые
    в таблицу, не посчитались дважды.

- **Карточка заказа** (`/order.html?id=…`) открывается в режиме просмотра — только чтение: получатель, доставка
  и треки, товары с серийниками (клик по серийнику — в «Серийные номера»), итоги, чеки. Правка — кнопкой
  «✎ Редактировать» (адрес `?edit=1`); «Отмена» отбрасывает несохранённые изменения, после сохранения
  заказ снова открывается на просмотр.

## Запуск

```bash
npm install   # один раз — подтягивает pdfkit/svg-to-pdfkit/bwip-js для этикеток
node server.js
# либо
npm start
```

Открыть http://localhost:3000. Порт можно поменять переменной `PORT`.

Данные хранятся в файле `data/orders.db` (SQLite, создаётся автоматически).

## Чего пока нет и почему

1. **Автоматическое получение заказов из ВК.** Пробовали через `market.getOrders`
   (раздел «Товары» сообщества) — метод недоступен по токену сообщества, нужен токен
   пользователя (админа группы), а получение такого токена у ВК сейчас требует
   регистрировать своё приложение на новом портале dev.vk.ru (старый api explorer убрали).
   Отложили эту интеграцию — если понадобится вернуться, код можно восстановить из
   истории git (ветка содержала `lib/vk.js` и `/vk.html`) и продолжить с того места.
   Пока заказы из переписки ВК заводятся вручную через форму «Новый заказ», а отправка
   оформляется через Ozon Delivery (см. выше).
2. **Синхронизация с Google Таблицами напрямую (не через CSV).** Нужен сервисный
   аккаунт Google (JSON-ключ) с доступом к вашей таблице — тогда добавляется
   вызов Google Sheets API при каждом создании/изменении заказа. Пока сделан CSV-экспорт,
   который так же попадает в Таблицы, но вручную.
3. **Автоматическая выдача чека из «Мой налог».** Официального публичного API нет; есть
   только личный кабинет физлица (lknpd.nalog.ru) с вашим логином/паролем/ИНН — заводить
   туда чужой сайт небезопасно. Зато сам чек (или скриншот оплаты) можно прикрепить к
   заказу вручную — см. «Чеки» выше.

**Важно про Ozon Доставка:** код интеграции написан строго по документации Ozon Delivery
API, которую вы прислали, но **ни разу не проверен живым запросом к api-delivery.ozon.ru** —
из этого окружения все поддомены `ozon.ru` недоступны по сети (заблокированы на уровне
прокси песочницы), точно так же как ранее не получилось проверить ВК API. Перед боевым
использованием проверьте на своей машине по порядку:
1. Сохраните `Client ID`/`Client Secret` в Настройках (`/settings.html`) и убедитесь, что токен получается
   (если получение падает — смотрите текст ошибки, он приходит от Ozon как есть).
2. Найдите dropoff- и return-точку и создайте метод отгрузки — дождитесь статуса «активен».
3. На тестовом заказе с реальным `delivery_point_id` покупателя пройдите «Рассчитать
   доставку» → «Создать черновик» → «Подтвердить к отгрузке» → «Этикетка PDF».
Особое внимание — на анти-бот редирект (testcookie): если Ozon начнёт стабильно отвечать
редиректом без выдачи cookie, `lib/ozon.js` (`rawRequest`) — то место, которое эту логику
реализует, и его придётся донастроить по фактическому поведению API.

## Структура

```
server.js       — HTTP-сервер и API
db.js           — SQLite-схема, каталог моделей/цветов/разъёмов/товаров, генератор серийников, бухгалтерия
lib/ledger-import.js — разбор строк, вставленных из Google-таблицы, для импорта в бухгалтерию
lib/serials-import.js — разбор листа «Продажи» для импорта серийных номеров
lib/label.js    — генерация PDF-этикетки 58×40мм
lib/ozon.js     — клиент Ozon Delivery API (OAuth client_credentials, testcookie-редирект)
public/         — фронтенд (index/board/orders/serials/order/ozon + style.css + app.js)
assets/         — шрифт DejaVu Sans (кириллица в PDF, свободная лицензия) и лого RU
Logo.svg, ru.svg — исходные логотипы TACLAB
data/           — файл базы данных и загруженные чеки (не в git)
```
